# JanjaCast localization

JanjaCast ships in **en-US** and **pt-BR**. Brazilian Discord users are the
primary audience, so pt-BR is not a translation layer bolted onto an English
product — it is the register the product is written *for*, and English is the
second locale that has to keep up.

Source of truth is the code:

| Layer                        | File                     |
| ---------------------------- | ------------------------ |
| Dictionaries, `t()`, plurals | `web/src/i18n.ts`        |
| The EN \| PT control         | `web/src/LangToggle.tsx` |
| Discord-client locale probe  | `web/src/discord.ts` → `fetchClientLocale` |
| Toggle placement / metrics   | `web/src/theme.css` → `.lang-seg`, `.header-lang`, `.share-lang` |

---

## 1. Why this matters more than usual here

Discord suspended Go Live, screen share and video calls **in Brazil** on
17 August 2026, by order of the ANPD. Voice, text and servers still work;
the picture does not. A screen-sharing Activity that runs inside the voice
call is, right now, the thing a Brazilian server reaches for when somebody
says "compartilha a tela aí" — and the person saying it is not reading
English UI. Getting the Portuguese right is the product, not a nicety.

Sources consulted for the terminology below: Discord's own pt-BR support
material (its Go Live article is titled *"Transmissões e compartilhamento de
tela"*), Brazilian tech press walkthroughs of the pt-BR client (Tecnoblog,
Filmora BR), and the vocabulary Brazilian Discord communities actually use in
chat.

---

## 2. Terminology

The rule: **the noun comes from Discord's pt-BR client, the verb comes from
how people talk.** A Brazilian must never have to translate our word back
into Discord's word to know what a control does.

| English (ours)   | pt-BR (ours)                | Discord pt-BR / rationale |
| ---------------- | --------------------------- | ------------------------- |
| Share screen     | **Compartilhar tela**       | Discord's own term, verbatim. Not "espelhar", not "exibir". |
| screen sharing   | **compartilhamento de tela** | Discord's support article title. |
| stream (verb)    | **transmitir**              | Discord's verb. "Streamar" exists in speech but is not what the client says. |
| stream (noun)    | **transmissão**             | Discord's noun. |
| Start sharing    | **Começar a transmitir**    | "Começar" over "Iniciar": iniciar is what a form does, começar is what a person does. |
| Stop sharing     | **Parar de transmitir**     | Discord's phrasing for ending a Go Live. |
| On air           | **Ao vivo** → renders `AO VIVO` | The badge Discord puts on a streaming member. `.live-badge-label` uppercases it, so the dictionary holds sentence case. |
| watching         | **assistindo**              | Discord says "Assistindo" for viewers of a stream. |
| sharing (roster tag) | **ao vivo**             | See § 3 — the exact verb "transmitindo" does not fit the sidebar. |
| Fullscreen       | **Tela cheia**              | Discord's term. |
| Framerate        | **Taxa de quadros**         | Discord's stream-quality setting. Six characters longer than English — see § 5. |
| Volume           | **Volume**                  | Identical; left alone. |
| voice call       | **call**                    | See § 3 — the one deliberate anglicism. |
| Activity         | **Atividade**               | Discord's own name for embedded apps in pt-BR. |
| room             | **sala**                    | JanjaCast's own concept, not Discord's; "sala" is the natural Portuguese and count-agnostic. |
| the stage        | **o palco**                 | JanjaCast's own metaphor. It survives translation intact — "assumir o palco", "tirar do palco" read as the same joke in both languages. |
| Advanced         | **Avançado**                | Standard. |
| Sound            | **Som**                     | Standard. |
| Optimize for     | **Otimizar para**           | Standard. |

**Not translated, ever:** the JanjaCast wordmark; units and codec names
(`fps`, `kbps`, `ms`, `Mbps`, `MB`, `KB`, `AV1`, `H.264`); the feature name
*Stingers*, which is JanjaCast's own coinage and has no Portuguese
equivalent that would not need explaining.

## 3. Register decisions

The crayon identity licenses informal copy (design.md § 1). Portuguese has a
sharper formal/informal split than English, so "the same tone" is a choice
that has to be made string by string. The line drawn here:

**Informal where the app is talking *to* you. Full verbs where you are about
to act.**

| Decision | What we ship | Why not the literal one |
| -------- | ------------ | ----------------------- |
| **"call", not "chamada de voz"** | *"todo mundo na call assiste pela Atividade"* | Nobody in a Brazilian Discord server says "chamada de voz". They say "call" — "entra na call", "tô na call". Using the formal noun in a hand-drawn app about hanging out with friends is the single most obvious tell that a product was translated rather than written. |
| **"tá", not "está"** | *"🎥 Você tá ao vivo a 60 fps."*, *"ninguém tá vendo sua tela agora"* | Used in exactly the two places the app narrates your own state back to you. The English there is equally loose ("You are live"). It is *not* used in labels, buttons or hints — a button that says "tá" reads as sloppy, a caption that says "está" reads as a manual. |
| **"Bora, minha vez"** for *Yeah, my turn* | takeover modal | "Sim, minha vez" is a translation of the words; "Bora" is a translation of the *feeling*. This modal is the app's most informal moment in English too. |
| **"Deixa pra lá"** for *Never mind* | takeover modal | "Cancelar" would be correct and dead. The pair Bora / Deixa pra lá is how the choice would actually be spoken. |
| **"aba", not "guia"** | *"Deixe esta aba aberta"* | Both are correct pt-BR for a browser tab; "aba" is what Brazilians say, "guia" is what Microsoft documentation says. |
| **"dá eco!"** for *echo-prone!* | audio mode option | "propenso a eco" is a lab report. "dá eco" is the warning a friend gives you. |
| **"Surpreenda a sala"** | stingers | Kept imperative and slightly formal-polite — it is a button that does something to *other people*, and the mild politeness is the joke. |
| **"Jogue um meme e uma buzina aqui dentro"** | empty stingers panel | "airhorn" has no single pt-BR word; "buzina" is what the meme sound is called in practice. |
| **"Assumir o palco"** for *Take the stage* | footer | The stage metaphor is JanjaCast's, not Discord's, so there is no official term to defer to. "Assumir" carries the taking-it-from-someone edge that "Entrar no" does not. |
| **"começo / fim"** for the `start` / `stop` stinger chips | stingers | Lowercase nouns, matching the English chips, and short enough for a 24px chip. "início/fim" also works; "começo" pairs better with the drawer's playground voice. |
| **"ao vivo", not "transmitindo"**, on the roster tag | sidebar | "transmitindo" is the exact verb and five characters too long: in a 186px sidebar it pushes the tag onto its own line for almost every name, and the tag is meant to read as the person's *suffix*, not a column (design.md § 5.5). "ao vivo" is Discord's own badge word for a streaming member, matches our header badge word-for-word, and is exactly as wide as English's "sharing". The three presence components agreeing is the rule, not a redundancy. |

Two things deliberately **not** made informal:

- **Error copy.** `⛔ A sessão expirou — volte pro Discord e clique em
  Compartilhar tela de novo.` uses "pro" but keeps full sentences and full
  verbs. Errors are the moment to be clear, and design.md § 5.9 already says
  they lead with a glyph and say what to do.
- **The accessibility layer.** `aria-label`s and `.u-sr-only` text are plain
  and complete ("Português (Brasil)", "Conexão: reconectando"). A screen
  reader user is not enjoying our voice; they are trying to find out what is
  happening.

## 4. How detection works

Zero friction is the goal: a Brazilian whose Discord is in Portuguese should
never see an English screen, and should never have to find a setting.

```
?lang=          →  localStorage("jc-lang")  →  navigator.languages  →  "en"
                                     ↑
        Discord client locale (async, after first paint) fills in
        only when none of the above answered
```

1. **`?lang=`** — how the Activity hands its language to the companion tab.
   `/share` lives on the public origin, the Activity lives on Discord's
   `/.proxy/`, so the two cannot share localStorage. `openCompanion()` puts
   the current locale on the URL and the tab opens already speaking it. It
   outranks a stored value because it is the fresher intent, and it is *not*
   written to storage — a direct visit to `/share` still gets whatever that
   browser last chose there.
2. **localStorage `jc-lang`** — the manual override. Written only by the
   toggle.
3. **`navigator.languages`** — the synchronous fallback, so the very first
   paint is already in the right language.
4. **`sdk.commands.userSettingsGetLocale()`** — the Discord client's own
   language (`discord.ts → fetchClientLocale`). It needs the `identify`
   scope, which `setupIdentity()` has already taken, so it is called *after*
   identity resolves and lands a beat after first paint; `t()` is reactive,
   so the whole tree re-renders. It returns `null` outside Discord, on older
   clients without the command, and on any RPC failure. **It never overrides
   an explicit choice** (`?lang` or localStorage) — that is the contract of
   the toggle.

Anything that is not `pt*` or `en*` falls through to the next source rather
than landing on a language nobody asked for. `document.documentElement.lang`
is kept in sync on every switch.

## 5. The toggle

`EN | PT`. A choice with exactly two crayons, so it is `.seg` and nothing
else (design.md § 5.2): state in `aria-pressed`, chrome-blue pressed fill,
no `.is-active` class. Only the metrics differ from the framerate control —
`.lang-seg` drops the cell from 46px to 38px (32px under 460px), still
clearing SC 2.5.8's 24×24 inside the 3px group border. The two visible
letters are an abbreviation, so each button carries the language's own name
as its `aria-label` and `title`; a screen reader says "English", not "E N".

Two placements:

- **Activity header**, pinned right (`.header-lang { margin-left: auto }`)
  with the connection dot immediately after it — language is chrome, the dot
  is status, and status sits at the very edge.
- **`/share`**, absolutely positioned in the top-left corner
  (`.share-lang`), opposite the sun, tilted +1.5° so it does not share an
  angle with the sheet or the card.

## 6. Layout: pt-BR runs 20–30% longer

Verified at 980px, 560px and 440px, in both languages, with a live room
(on-air badge + stats pill present). Three things had to move:

| Change | Why |
| ------ | --- |
| `.app-header .stat-pill { display: none }` at ≤620px | The header does not wrap. A live room fills it with the lockup, the on-air badge, the stats, the toggle and the connection dot, and adding ~86px of toggle pushed it over. The stats go at the same tier the status line already goes: they are diagnostics (design.md § 5.6, "the identity steps back completely"), the badge — *who is live* — outranks them, and `.stage-stats` still carries them in fullscreen and theater, which is where anyone reading 4200 kbps is actually looking. |
| `.share-card .crayon-details .crayon-select` 330px → **352px** | *"🎵 Som do app — sem eco na call (recomendado)"* measures 304px in the Hand face and needs 348 once the 10px inset, the 30px chevron gutter and the borders are added. At 330 it ran under the chevron. The panel's content box is 424px, so both rows still fit their label inline. |
| `.lang-seg .seg-btn` 38px → 32px at ≤460px | Two capitals do not need a framerate cell, and the narrow Activity panel has none to spare. |

Nothing else wrapped or overflowed. Specifically checked: the footer
(*Taxa de quadros* is the longest label and the footer wraps by design), the
scene CTA (*Compartilhar tela* is 5 characters longer than *Share screen*
and the button is sized by its content), the roster tags (*transmitindo* /
*você*), the on-air badge (the publisher's name truncates, the badge does
not), and the stinger chips (*começo | fim | on*).

**When you add a string,** check it at 440px on both grounds before you
commit. The two shapes that break first are a fixed-width control (the
selects) and a non-wrapping row (the header).

## 7. Adding a locale

1. Add the tag to `Locale` in `web/src/i18n.ts`.
2. Add a plural rule to `pluralRule`. English and pt-BR already differ:
   CLDR's `pt` puts `i = 0..1` in the `one` bucket, so Portuguese says
   "0 pessoa" where English says "0 people". Anything interpolating a count
   cannot reuse the English branch.
3. Add one dictionary typed `Record<MessageKey, Message>`. **TypeScript then
   refuses to build until every key is translated** — that is the whole point
   of typing the maps off `en`.
4. Add the tag to `normalizeLocale()` so detection can reach it.
5. Add a button label (`lang.xx` / `lang.xx.full`) and extend `LOCALES`.
   Three or more locales stop being a segmented control and become a
   `.crayon-select` — design.md § 5.2 is explicit that three options is a
   select, and there is to be no three-segment toggle.

### Writing messages

- **One sentence, one message.** Never concatenate fragments: word order
  around an interpolated number is not the same in every language. This is
  why `stage.liveHere` and `stage.liveTab` are two whole sentences rather
  than a shared prefix plus a suffix.
- **Slots are named**: `t("modal.kick", { name })` fills `{name}`. Calling
  `t()` with no params leaves the placeholder in the string — which is how
  the takeover modal splits its one message around the slot and keeps the
  name in `<strong>`.
- **Counts go through the plural machinery**, even when both English forms
  happen to be identical. `share.watching` carries an optional `zero` form
  because "nobody watching" / "ninguém assistindo" beats "0 watching".
- **Errors are stored as descriptors, not rendered strings.** `App.tsx` and
  `SharePage.tsx` hold `{ key, params }` in the error signal so an error
  already on screen re-draws when the language flips. A bare string is the
  escape hatch for text we do not own.

### What is deliberately not localized

- **Everything in `player.ts`, `capture.ts`, `session.ts`, `protocol.ts` and
  the Go server.** Those strings are `console.error` and wire-protocol text:
  developer-facing, and English is the right language for a stack trace.
- **Browser and platform messages.** `getDisplayMedia` rejections
  (`NotAllowedError: Permission denied`) reach the error line verbatim; they
  are already localized by the browser, in the *browser's* language.
- **Server-side upload rejections.** The stinger panel renders
  `⛔ <file>: <reason>` where `<reason>` comes from `internal/server`. The
  frame is translated; the reason is the Go server's English. Localizing it
  would mean either shipping message ids over the wire or duplicating the
  server's validation rules in the client — both are worse than one English
  clause in a rare error.
